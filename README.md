# DYNASTY FAMILY Bot v5 — руководство для начинающих

**Версия:** 5.0. Для Python **3.11+**, `discord.py==2.7.1`, база SQLite.

## Что изменено

- **Одна Slash-команда `/menu`** для всех операций настройки. Меню видят только администраторы сервера. Дополнительно обработчики в каждом окне перепроверяют права администратора и пользователя, открывшего меню.
- В меню можно по отдельности настроить: первичную установку каналов; роли Crime и State; общую роль всем одобренным; роль модератора; голосовой канал обзвона; список до **50 ролей** для уведомлений; сброс зависшей заявки.
- Раздел **«Публикация»**: независимо обновить **панель заявок**, **голосовой пульт и канал создания комнат**, **журнал заявок** и **журнал голосовых комнат**. Если нужный канал удалён — бот попытается восстановить его и обновить ID в базе. Другие панели при этом не затрагиваются.
- При нажатии модератором «Вызвать на обзвон» кандидат получает тег в приватной ветке и личное сообщение. Если за 5 минут он не подключился к назначенному голосовому каналу, бот **отклоняет заявку, но НЕ исключает участника с сервера**. Кандидат получает ЛС, полный результат записывается в журнал заявок, ветка удаляется. Если кандидат подключился вовремя — автоматический отказ отменяется; заявка ожидает ручного решения.
- **Ручная** кнопка «Отклонить» по-прежнему исключает участника, как в предыдущей версии. При ручном одобрении выдаются две роли: Crime или State + общая роль.
- Для голосовых комнат добавлен настраиваемый журнал событий: создание, удаление, передача владения и настройки. Журнал существует только после его публикации; при первичной установке создаётся автоматически.
- Отправленные заявки, настройки серверов и список владельцев голосовых комнат хранятся в `data/bot.sqlite3`, структура старой базы обновляется автоматически при запуске.

## 1. Как обновить уже работающего бота через GitHub и хостинг

1. **Остановите запущенный процесс бота** на хостинге. Не запускайте одновременно старую и новую версии.
2. Через файловый менеджер хостинга **скачайте резервную копию** `data/bot.sqlite3`, особенно если сервис пересоздаёт контейнер при обновлении.
3. Распакуйте архив `DYNASTY_FAMILY_v5_UPDATE.zip` и в вашем **существующем репозитории GitHub** замените `bot.py` и `storage.py`. Можно также обновить `README.md`, `tests/test_storage.py` и добавить `CHANGES_V5.md`. Коммитните изменения (**Commit changes**).
4. В панели хостинга проверьте подключение репозитория и текущей ветки. Запустите **Redeploy/Rebuild** (или `git pull`, если автодоставка кода не включена). Обычный Restart не всегда скачивает новую версию из GitHub.
5. На сервере должны устанавливаться зависимости из `requirements.txt` и выполняться команда `python bot.py`. **Не** `python server.py`.
6. В разделе переменных окружения хостинга задайте `DISCORD_TOKEN`, `GUILD_ID` и `DATABASE_PATH` (пример ниже). **Никогда не загружайте `.env` с токеном на GitHub**.
7. Запустите контейнер. Для работы на нескольких Discord-серверах укажите `GUILD_ID=0`; тогда регистрируется глобальная команда `/menu`. В логе ищите `Synced 1 global slash commands` и `Bot logged in as ...`.
8. Откройте Discord, в канале сервера введите `/menu`. При отсутствии команды проверьте scopes `bot` и `applications.commands` в Discord Developer Portal → Installation, права интеграции на сервере и обновите клиент (`Ctrl + R`).

Если в старой версии команды `/setup_server` и `/set_application_roles` были зарегистрированы только на одном сервере, v5 при первом старте с `GUILD_ID=0` пытается удалить устаревшие серверные регистрации на серверах, которые уже есть в базе данных. Это **не** удаляет каналы и роли. Если сервер недоступен боту, очистка его команд может не состояться; ошибка будет в логе.

### Переменные окружения

```dotenv
DISCORD_TOKEN=СЕКРЕТНЫЙ_ТОКЕН_ИЗ_DISCORD_DEVELOPER_PORTAL
GUILD_ID=0
DATABASE_PATH=data/bot.sqlite3
```

В реальном `.env` укажите настоящие значения. На хостинге безопаснее пользоваться разделом **Environment / Variables** и не хранить `.env` в GitHub. `GUILD_ID=0` подходит для нескольких серверов; если хотите регистрировать `/menu` только на одном тестовом сервере, укажите его ID. При публикации глобально команды могут не появиться моментально.

**Внимание к SQLite:** на Docker-хостинге необходимо подключить **постоянный диск/volume для папки `data/`**. Без него база может исчезнуть после пересборки контейнера. Само обновление v5 базу не удаляет.

## 2. Первоначальная настройка сервера с нуля

1. Создайте в Discord четыре роли: **Crime**, **State**, **Модератор**, **DYNASTY Member** (названия произвольные).
2. В настройках ролей расположите роль бота выше ролей Crime, State и DYNASTY Member.
3. Проверьте права бота: управление каналами, ролями, ветками, отправка сообщений/Embed, управление участниками, перемещение участников. В Discord Developer Portal → **Bot** включите **Server Members Intent**.
4. В канале Discord введите `/menu` **с аккаунта администратора**.
5. Нажмите **«Первичная настройка»**. Выберите четырьмя селекторами Crime, State, Модератор и общую роль; нажмите **«Сохранить»**.
6. Бот создаст `#подать-заявку`, `#журнал-заявок`, `➕ Создать комнату`, `#управление-комнатой`, `#журнал-комнат` и нужные категории. Панели будут отправлены автоматически.
7. Откройте `/menu` → **«Канал обзвона»** и выберите уже созданный голосовой канал для собеседований. При необходимости создайте его вручную в Discord.
8. Через `/menu` → **«Упоминания»** выберите роли администрации для уведомления о новых заявках.

### Что находится в `/menu`

| Кнопка | Назначение |
|---|---|
| Первичная настройка | Создать каналы на ещё не настроенном сервере |
| Crime / State | Назначить направление и роль для одобрения |
| Общая роль | Настроить вторую, обязательную роль для каждого одобренного |
| Модераторы | Изменить роль, которой доступны решения по заявкам |
| Канал обзвона | Выбрать голосовой канал для пяти минут ожидания |
| Упоминания | Выбрать до 50 ролей по 25 за раз, добавить/убрать/очистить |
| Публикация | Переотправить только выбранный элемент |
| Сброс заявки | Выбрать пользователя и удалить его зависшую заявку |
| Обновить статус | Показать текущее состояние настроек и ID каналов |

После изменения настроек можно вернуться кнопкой **«← В меню»**. Меню **личное (ephemeral)**; через 10 минут неиспользуемая панель перестаёт отвечать — снова вызовите `/menu`.

## 3. Как независимо опубликовать один элемент

Выполните `/menu` → **«Публикация»**. Далее выберите **ровно одну** кнопку:

- **📝 Заявки** — заново отправляет Embed с баннером и кнопкой «Подать заявку» в `#подать-заявку`. Если канал удалён, создаёт новый канал и обновляет сохранённый ID. Сохранённое ботом предыдущее сообщение панели по возможности удаляется. **После первого обновления со старой версии** старую панель, если она осталась, удалите вручную.
- **🎧 Голосовые** — заново отправляет панель с 13 кнопками в `#управление-комнатой`. Если удалён канал управления, голосовой канал `➕ Создать комнату` или категория, восстанавливает недостающие элементы и меняет их ID в базе. Уже существующие временные голосовые комнаты не затрагиваются.
- **📋 Логи заявок** — создаёт заново `#журнал-заявок` только если он отсутствует, иначе оставляет прежний канал; публикует информационное сообщение. Полные анкеты и решения **продолжают логироваться при новых событиях**. Если старый канал удалён, утраченные сообщения из него не восстанавливаются автоматически.
- **📒 Логи комнат** — создаёт заново `#журнал-комнат` при необходимости и публикует информационное сообщение. Дальнейшие события голосовых комнат записываются туда. В старых установках этот канал может отсутствовать до первой публикации.

**Нельзя** безопасно восстановить историю удалённых текстовых сообщений Discord по одной записи об ID в SQLite. Обновление одной панели **не удаляет** другие панели, каналы или базу.

## 4. Как работают заявки и обзвон

1. Участник нажимает кнопку «Подать заявку», вводит ник, числовой статик, имя и возраст, выбирает Crime/State, пишет историю знакомства с семьёй.
2. Бот создаёт **приватную ветку внутри `#подать-заявку`**, упоминает выбранные роли модерации и отправляет Embed анкеты с кнопками **«Принять», «Отклонить», «Вызвать на обзвон»**.
3. По вызову кандидат добавляется во ветку, получает тег и ЛС с указанным голосовым каналом и крайним сроком пять минут.
4. Если кандидат вошёл в нужный голосовой канал вовремя — бот фиксирует явку, отменяет автоматический отказ; решение остаётся за модераторами.
5. Если кандидат **не вошёл за пять минут**, заявка автоматически отклоняется, в журнал заносится **полная анкета** и причина отказа, бот сообщает кандидату в ЛС и удаляет ветку. **Кандидат остаётся на сервере; кика нет**.
6. При **ручном** «Принять» кандидат получает Crime **или** State и общую роль. При **ручном** «Отклонить» кандидат исключается с сервера (требуется `Kick Members`).

Если личные сообщения у кандидата закрыты, отправка ЛС может не сработать. Об этом делается отметка в журнале заявок.

## 5. Управление голосовыми комнатами

Участник входит в `➕ Создать комнату`, бот создаёт отдельную комнату и перемещает его туда. Владелец, находящийся в своей комнате, управляет 13 кнопками в `#управление-комнатой`: лимиты, открыть/закрыть, скрыть/показать, изменить имя, выдать/убрать доступ, блокировать/разблокировать человека, передать владение, удалить комнату. Пустая временная комната удаляется автоматически. События записываются в `#журнал-комнат`, если этот канал настроен.

## 6. Запуск на компьютере Windows в VS Code

В терминале PowerShell, находясь в папке с `bot.py`:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe bot.py
```

Если виртуальное окружение уже создано, **не повторяйте** первую команду. Запуск через `.\.venv\Scripts\python.exe` не требует выполнения PowerShell-скрипта `Activate.ps1`.

## 7. Проверки и устранение проблем

- **`Synced 1 global slash commands`** — глобальная команда `/menu` зарегистрирована успешно. При `GUILD_ID` для одного сервера возможен лог `Synced 1 slash commands to server ...`.
- **`403 Forbidden / 50001 Missing Access`** — нет доступа к каналу/серверу или бот не установлен должным образом. Проверьте ID сервера, установку, права.
- **Ветки не создаются** — проверьте у бота `Create Private Threads`, `Manage Threads`, `Send Messages in Threads`, `View Channel` и у роли модераторов — `Manage Threads`.
- **Роли не выдаются** — роль бота ниже выдаваемых ролей либо нет права `Manage Roles`.
- **Уведомления ролей не приходят** — у ролей нет доступа к приватной ветке либо у бота нет права упоминать их.
- **Новый `/menu` отсутствует** — проверьте, что загружен новый `bot.py`, успешно прошёл Redeploy, Discord-интеграция использует `applications.commands` и ограничения каналов/ролей не блокируют команду.
- **Контейнер ищет `server.py`** — проверьте Startup/Entrypoint и задайте `python bot.py`.
- **База исчезает после развёртывания** — используйте постоянный том для `data/`.

### Локальные тесты

```bash
python -m unittest discover -s tests -v
python -m py_compile bot.py storage.py
```

Тесты проверяют миграцию и логику SQLite **без подключения к Discord**. Полноценные нажатия кнопок, выдачу ролей и разрешения нужно проверить **на тестовом Discord-сервере** перед эксплуатацией в основном сообществе.
