# DYNASTY FAMILY BOT v8 — инструкция для начинающих

**Игра:** Majestic RP, сервер **Miami**. **Python:** 3.11+. **Библиотека:** `discord.py==2.7.1`. **Хранение:** SQLite.

Это продолжение бота v6. **Системы контрактов здесь нет**. Добавлены модуль капт-состава и личный кабинет участника. Все старые функции заявок, обзвонов, ролей и временных голосовых комнат сохраняются.


## Обновление v8 — выбор даты и результата капта

В версии v8 капитан **выбирает исход капта из выпадающего списка** («Победа», «Поражение», «Ничья»), а **дату и время выбирает отдельными списками**, без ручного набора. Доступен выбор ближайших 365 дней с переключением страниц по 25 дат, часы 00–23, минуты кратны пяти. В форме создания теперь четыре поля (противник, место, формат, количество мест). После выбора даты и времени капитан нажимает «Опубликовать капт». Итог, напоминания, роль анонсов и статистика работают как раньше.

**Для обновления v7 → v8** достаточно заменить один файл `family_features.py` из архива `DYNASTY_FAMILY_v8_UPDATE.zip`, сделать Commit в GitHub и выполнить Redeploy/Rebuild на хостинге. **Dockerfile не меняется**, SQL-миграция не нужна. База SQLite, `.env`, `bot.py`, `storage.py`, `family_storage.py`, `family_rewards.py` сохраняются. Полная пошаговая инструкция — в `CHANGES_V8.md`.

Примечание: это выбор даты из списка, а не календарная сетка; штатного календарного элемента для используемой версии Discord API нет.

## 1. Что добавлено

### Капт-состав

1. Администратор вводит `/menu` и нажимает **«⚔️ Капт-состав»**.
2. В этом разделе настраиваются каналы `#капт-состав`, `#журнал-каптов`, закрытый `#проверка-откатов`, роль капитана, часовой пояс и голосовой канал для сбора. **Каждая публикация выполняется отдельно**.
3. Капитан создаёт капт по кнопке «Создать капт»: противник, место/квадрат, формат, максимальное число участников основного состава. Затем выбирает дату и время из списков и нажимает «Опубликовать капт».
4. В `#капт-состав` публикуется Embed с кнопками:
   - **«Участвую»** — записаться в основной состав, если есть места;
   - **«Резерв»** — добровольно записаться в резерв;
   - **«Не смогу»** — снять участие;
   - **«Сдать откат»** — передать ссылку на видеозапись и комментарий на проверку;
   - **«Полный состав»** — просмотр всего списка по страницам;
   - **«Явка»** — только капитан/администратор, отметить участников как присутствовавших или отсутствовавших;
   - **«Завершить»** — только капитан/администратор: сначала выбрать победу / поражение / ничью из списка, затем при необходимости указать ссылку на видео и комментарий;
   - **«Отменить»** — только капитан/администратор, отменить капт с подтверждением.
5. Если основные места заняты, новые участники попадают в резерв. Когда место освобождается, бот продвигает самого раннего резервиста, пытаясь отправить ему уведомление в ЛС.
6. В канале каптов бот напоминает о ближайшем мероприятии примерно за **30, 15 и 5 минут**, отмечая записанных в основной состав. Таймеры сохраняются после рестарта в базе.
7. В журнал записываются создание, результат, отмена капта, подтверждения явки, решения по откатам.

**Важно:** бот **не читает результаты из игры**. Капт-лидер вводит исход боя и отмечает фактическую явку вручную. Нахождение в Discord-голосовом канале само по себе не подтверждает участие в капте.

### Личный кабинет

У каждого участника есть команда **`/profile`** (видна на сервере независимо от прав администратора).

- Игровой ник, числовой статик `#`, направление **Crime / State** из Discord-ролей.
- Текущая роль на сервере Discord.
- Подтверждённые посещения каптов, победы и поражения, будущие записи в основу, количество одобренных откатов.
- Базовые достижения по числу подтверждённых посещений.
- Кнопки **«Изменить ник / статик»**, **«Мои капты»**, **«Обновить»**.

Все ответы личного кабинета **приватны** (Discord ephemeral). **Имя и возраст IRL не попадают в профиль**. Если заявка уже была принята на v5, участник открывает `/profile` и заполняет ник и статик самостоятельно. Для новых одобренных заявок сведения автоматически добавляются из анкеты.

## 2. Обновление v5 → v6 через GitHub

**Перед началом:** скачайте резервную копию `data/bot.sqlite3` из файлового менеджера своего хостинга и убедитесь, что для `data/` используется постоянное хранилище. Не удаляйте текущую базу.

1. На хостинге нажмите **Stop** (остановить бота). Не запускайте одновременно две версии с одной базой.
2. Скачайте архив **`DYNASTY_FAMILY_v6_UPDATE.zip`**, распакуйте его на компьютере.
3. Откройте свой репозиторий GitHub, перейдите во вкладку **Code** и загрузите **с заменой файлов**:
   - `bot.py` (**заменить** старый);
   - `storage.py` (**заменить** старый);
   - `family_features.py` (**новый**);
   - `family_storage.py` (**новый**);
   - `requirements.txt` (**заменить**, добавлен `tzdata` для часовых поясов);
   - `README.md` и `CHANGES_V6.md` (необязательно, но рекомендуется);
   - `tests/test_family.py` (необязательно для хостинга).
4. Проверьте, что **`bot.py`, `storage.py`, `family_features.py`, `family_storage.py`, `requirements.txt` находятся в одной и той же корневой папке репозитория**, рядом с вашим `Dockerfile`, если он есть. Не размещайте их внутри дополнительной папки `v6/`.
5. Нажмите на GitHub **Commit changes** для сохранения изменений.
6. В панели хостинга нажмите **Deploy / Redeploy / Rebuild** (кнопка зависит от сервиса). Обычный Restart иногда **не скачивает новую версию с GitHub**.
7. Команда запуска хостинга: **`python bot.py`**. Установка зависимостей: **`pip install -r requirements.txt`**. Если используется Docker, убедитесь, что Dockerfile устанавливает все зависимости и вызывает `bot.py`.
8. Переменные окружения должны содержать следующее:

   ```dotenv
   DISCORD_TOKEN=секретный_токен_бота
   GUILD_ID=0
   DATABASE_PATH=data/bot.sqlite3
   ```

   **Не загружайте `.env` в GitHub.** Вместо этого используйте вкладку Environment / Variables на хостинге. `GUILD_ID=0` подходит, если бот добавлен на несколько Discord-серверов. **Токен никогда не показывайте в скриншотах**.

9. Запустите бота. В логах ожидается `Synced 2 global slash commands` при `GUILD_ID=0` — `/menu` и `/profile`.
10. В Discord с правами администратора откройте `/menu` → **⚔️ Капт-состав** → **Создать каналы**. Первичная настройка v5 уже должна быть выполнена.
11. В том же разделе нажмите **«Роль капитана»** и укажите роль лидеров состава; **«Часовой пояс»** и **«Канал сбора»** настройте по необходимости.
12. Нажмите **«Публиковать панель»**; бот разместит панель с кнопками в `#капт-состав`. Зайдите туда и создайте первый тестовый капт.

**Если GitHub не даёт загрузить `.env`, это нормально.** Токен находится в переменных окружения сервера, а не в публичном репозитории.

## 3. Быстрый запуск с нуля

Скачайте полный архив v6. Он содержит старый функционал v5, новые модули, изображение стартовой панели, документацию и тесты.

```bash
python -m pip install -r requirements.txt
python bot.py
```

На Windows в VS Code (если окружение уже создано):

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe bot.py
```

Если виртуального окружения нет, создайте его с помощью `py -3.11 -m venv .venv`.

Для нового Discord-сервера администратор сначала выполняет в `/menu` **«Первичная настройка»**, выбирая Crime, State, модератора и общую роль. Только после этого открывает **«Капт-состав»** и нажимает «Создать каналы».

## 4. Раздел «Капт-состав» в `/menu`

| Кнопка | Что происходит |
|---|---|
| Создать каналы | Создаёт отсутствующие `#капт-состав`, `#журнал-каптов`, `#проверка-откатов`; существующие не удаляет |
| Создать капт | Открывает форму нового боя, доступна администратору |
| Роль капитана | Назначает роль для управления каптами и откатами |
| Часовой пояс | Выбор временной зоны (IANA), по умолчанию `Europe/Moscow` |
| Канал сбора | Выбор готового голосового канала; бот будет указывать его в напоминаниях |
| Публиковать панель | Обновляет **только панель капт-состава**, не затрагивает заявки, голосовые комнаты или журналы |
| Журнал каптов | Проверяет канал и публикует диагностическую запись |
| Журнал откатов | Показывает приватный канал рассмотрения видео |
| Статистика | Показывает ближайшие капты и топ участников по подтверждённой явке |
| Главное меню | Возврат к старым настройкам `/menu` |

Все настройки через `/menu` доступны **только администраторам**. Создать капт и управлять уже созданным событием также могут пользователи с ролью, назначенной кнопкой **«Роль капитана»**. Администраторы могут всё.

## 5. Пример капта

Капитан нажимает «Создать капт» и вводит:

```text
Противник: FAMILY X
Место: Квадрат 15
Формат: 15x15
Дата и время: 18.11.2026 20:30
Количество мест: 15
```

Форма интерпретирует дату в указанном в настройках часовом поясе. Discord показывает дату и время **по локальному часовому поясу участника**. Отдельно проверьте, что капитаны используют одну согласованную часовую зону (например, МСК). Формат 15x15 — только **пример**, не обязательный формат для Majestic RP Miami.

После создания участники нажимают «Участвую», «Резерв» или «Не смогу». Капитан может нажать «Полный состав» и пролистывать список, а после фактического события — «Явка», отметить тех, кто был на мероприятии, затем «Завершить» и записать результат. Явка может быть скорректирована и после записи результата.

Кнопка «Сдать откат» принимает **ссылку на видеозапись** (начинающуюся с `https://`) и необязательный комментарий. Сам файл видео бот не загружает в этот модуль, а размещает ссылку и кнопки модерации в закрытом `#проверка-откатов`.

## 6. Кто имеет доступ

- **Администратор сервера:** все настройки в `/menu`, создание каптов, назначение явки, завершение, отмена, проверка откатов.
- **Роль капитана:** создание каптов через панель `#капт-состав`, явка, завершение, отмена, проверка откатов; **не** доступ к `/menu`.
- **Член семьи** с ролью Crime, State или общей ролью: запись/резерв/отказ, подача отката по своему капту, личный кабинет.
- **Иные пользователи:** могут открыть свой `/profile`, но записаться в капт не смогут, пока у них нет семейной роли.

Роль бота должна иметь право **Manage Channels, View Channel, Send Messages, Embed Links**; для старого функционала остаются необходимые **Manage Roles, Manage Threads, Move Members, Kick Members** и другие. Права выдачи ролей определяются иерархией Discord. Закрытые каналы каптов должны быть видны только капитану, администраторам и боту.

## 7. Как сохранить данные при обновлениях

База данных находится по пути `data/bot.sqlite3`. Это **одна база** для заявок, комнат, профилей и каптов. Старые таблицы не удаляются; новые создаются автоматически при запуске. Важны два правила:

1. Хостинг должен сохранять папку `data/` между перезапусками и пересозданием контейнера (Volume / Persistent Storage).
2. Никогда не загружайте базу в GitHub. GitHub предназначен для файлов исходного кода.

Если у вас контейнер Docker, хранилище нужно привязать именно к `/app/data`, а переменную оставить `DATABASE_PATH=data/bot.sqlite3`. Если хостинг монтирует диск в другом пути, соответственно поменяйте значение `DATABASE_PATH`.

## 8. Проверка работы

На тестовом сервере:

1. `/menu` доступно администратору, не отображает настройки обычному участнику.
2. `/profile` показывает приватную карточку; изменение никнейма и числового статика сохраняется.
3. Создайте капт на будущее время с вместимостью 2 человека. Двое вступят в основу, третий окажется в резерве.
4. Один боец из основы нажмёт «Не смогу». Проверьте автоматический переход первого резервиста и уведомление в ЛС.
5. Капитан отметит явку, внесёт победу и убедится, что посещения/победы обновились только у отмеченных бойцов.
6. Отправьте ссылку через «Сдать откат», проверьте кнопки и приватные журналы.
7. Перезапустите бота и проверьте, что старые кнопки продолжают работать, а состав и история не исчезли.
8. Убедитесь, что **предыдущие заявки, обзвоны, временные голосовые комнаты** работают как раньше.

### Локальная проверка Python без Discord

```bash
python -m py_compile bot.py storage.py family_features.py family_storage.py
python -m unittest discover -s tests -v
```

Эти тесты проверяют SQLite и логику данных **без реального Discord**. Они не могут подтвердить доступы, нажатия кнопок и регистрацию в API Discord. Для этого нужен тестовый сервер.

## 9. Частые ошибки

| Ошибка | Решение |
|---|---|
| `ModuleNotFoundError: family_features` | Файлы `family_features.py` и `family_storage.py` не находятся рядом с `bot.py` |
| `ModuleNotFoundError: discord` | Установите библиотеки: `pip install -r requirements.txt` |
| `python: can't open file '/app/server.py'` | В Startup/Dockerfile должна запускаться `python bot.py` |
| Нет `/profile` | Проверьте новый код, Redeploy, scopes `applications.commands` и `GUILD_ID=0` |
| Капт-панель отсутствует | `/menu` → «Капт-состав» → «Создать каналы» → «Публиковать панель» |
| Нет доступа к журналу/откатам | Назначьте роль капитана, проверьте её права на приватные каналы |
| Время отличается от ожидаемого | Проверьте настройку часового пояса и дату в создаваемом капте |
| `403 Forbidden` | Проверьте разрешения бота и каналов |
| Не пришло ЛС | Настройки приватности пользователя могут запрещать личные сообщения |
| После Redeploy исчезли капты | Хостинг не сохраняет `data/bot.sqlite3`; подключите постоянный диск |

**Примечание по правилам Majestic RP Miami.** Поскольку правила войн семей и расписания могут меняться, бот не навязывает игровые лимиты, стороны и иные ограничения. Капитан сам указывает формат боя и несёт ответственность за соответствие актуальным правилам своего сервера.
