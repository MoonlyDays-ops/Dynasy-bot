# DYNASTY FAMILY — бот заявок и временных голосовых комнат

**Python 3.11+ · discord.py 2.7.1 · SQLite.**

Эта версия заменяет прежнюю анкету на пятичастную форму DYNASTY FAMILY. Голосовые комнаты и их 13 кнопок остаются прежними.

## 1. Что делает бот

**Заявки:**

1. В текстовом канале `#подать-заявку` публикуется Embed «DYNASTY FAMILY» с предоставленным вами изображением и кнопкой **«Подать заявку»**.
2. Нажатие открывает **настоящее модальное окно Discord** с пятью полями:
   - **Ник в игре** — текст;
   - **Статик #** — только символы `0–9`, без пробелов и `#`; ввод проверяется перед отправкой;
   - **Имя и возраст IRL** — одно текстовое поле, например `Александр, 20 лет`;
   - **Направление** — выпадающий список **Crime / State**, нужно выбрать один вариант;
   - **Как узнали о семье и были ли в других известных семьях?** — развёрнутый ответ.
3. Бот создаёт **приватную ветку непосредственно внутри `#подать-заявку`**. Обычные участники видят только панель с кнопкой, а **не чужие анкеты**. Модераторы с разрешением `Manage Threads` видят приватные ветки.
4. В ветке бот размещает Embed с ответами и кнопками **«Принять»** и **«Отклонить»**.
5. Если модератор принимает анкету Crime, выдаётся роль **Crime**; если State — **State**.
6. Если модератор отклоняет анкету, бот **исключает** пользователя с сервера (kick, не бан).
7. После решения ветка удаляется, в `#журнал-заявок` остаётся запись о решении и направлении. Ответы анкеты не копируются в журнал.
8. Бот пытается написать заявителю **в личные сообщения** при получении анкеты, одобрении и отказе. **Доставка ЛС не гарантируется**, если участник запретил сообщения от участников сервера либо блокирует бота; решение модератора при этом выполняется.
9. Одновременно можно иметь только одну активную заявку. Одно решение нельзя принять дважды.

**Голосовые комнаты:**

— При входе в `➕ Создать комнату` создаётся личный голосовой канал.

— В `#управление-комнатой` доступны **13 кнопок**: добавить/убрать слот, открыть/закрыть, добавить/убрать участника, заблокировать/разблокировать, скрыть/показать, переименовать, передать владение и удалить комнату.

— Когда все пользователи покидают комнату, она удаляется. Пока бот выключен, эта автоматизация не работает.

## 2. Если бот у вас УЖЕ настроен (важно!)

**Не удаляйте** существующие `.env` и `data/bot.sqlite3`: там находятся токен, ID сервера и все настройки ранее созданных каналов/ролей/комнат.

1. Остановите старую программу в терминале VS Code: нажмите `Ctrl + C`.
2. Закройте игру/проект, если кто-то сейчас отправляет заявку; завершите открытые заявки перед обновлением, если можете.
3. Сделайте копию старой папки проекта или хотя бы `data/bot.sqlite3`.
4. Распакуйте новые `bot.py`, `storage.py`, `README.md`, `requirements.txt` и **папку `assets`** в старую папку `discord_application_voice_bot`, согласившись на замену файлов. **Не перезаписывайте `.env` и `data/bot.sqlite3`**.
5. Откройте в VS Code **Terminal → New Terminal** и выполните:

   ```powershell
   cd "C:\Users\marcg\Desktop\discord_application_voice_bot"
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe bot.py
   ```

6. На сервере Discord должны существовать две роли `Crime` и `State`. Создайте их через **Настройки сервера → Роли**, если ещё не созданы. Переместите роль бота **выше обеих ролей** в списке ролей.
7. Администратор сервера вводит новую команду:

   ```text
   /set_application_roles crime_role:@Crime state_role:@State
   ```

   Команда сохранит два ID ролей и **добавит необходимые разрешения** в существующий канал `#подать-заявку` для приватных веток. Боту нужны права `Manage Channels`, `Create Private Threads`, `Manage Threads`, `Send Messages in Threads`, `Manage Roles`, `Kick Members`, `Attach Files`, `Embed Links`, `Read Message History`.

8. Затем администратор вводит:

   ```text
   /republish_panels
   ```

   Бот заново опубликует стартовую панель с изображением в `#подать-заявку` и панель голосовых комнат. **Старые сообщения с панелями можно удалить вручную** после проверки новых, чтобы не было двух кнопок «Подать заявку».

9. Проверка: `/bot_status` должна сообщить, что роли Crime/State настроены.

**Что сохранится после обновления:** SQLite автоматически дополняется новыми полями, старые записи и уже созданные голосовые комнаты не стираются. Старый `#проверка-заявок` останется, но **новые заявки туда не идут**. Удалять его можно только после закрытия всех старых заявок. Незавершённые старые заявки сохраняют свои прежние ветки и могут быть рассмотрены старой ролью участника.

**Если возникает `403 Missing Access`:** проверьте, что бот добавлен именно на сервер с указанным в `.env` `GUILD_ID`, а у него есть доступ к каналу и права создавать приватные ветки. В Discord Developer Portal → Bot также включите **Server Members Intent**.

## 3. Если создаёте сервер с нуля

1. Создайте нового бота в <https://discord.com/developers/applications> → **New Application** → **Bot**. Получите токен в разделе **Bot**. Токен нельзя никому пересылать.
2. Включите **Server Members Intent** в разделе **Bot** → **Privileged Gateway Intents**.
3. В разделе **Installation** установите scopes **`bot` + `applications.commands`** и пригласите бота на свой сервер.
4. Для первого теста на тестовом сервере можно временно использовать полномочие `Administrator`. Для обычного сервера рекомендуется назначить отдельные минимальные разрешения: просмотр/отправка сообщений, Embed Links, Attach Files, управление каналами/ролями/ветками, создание приватных веток, отправка сообщений в ветках, Kick Members, Move Members и Connect. Участник сервера должен иметь разрешение **Use Application Commands**.
5. Создайте роли **Crime**, **State**, **Модератор**. Роль бота должна стоять **выше Crime и State**, а при кике — выше ролей исключаемого пользователя. Владелец сервера не может быть исключён ботом.
6. В папке проекта в VS Code откройте терминал PowerShell и выполните:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   Copy-Item .env.example .env
   ```

   Если окружение уже существует, первую команду повторять не нужно. Виртуальное окружение **не нужно активировать**; мы запускаем его `python.exe` напрямую, чтобы избежать ошибок PowerShell.

7. Заполните `.env` в папке проекта:

   ```dotenv
   DISCORD_TOKEN=ВАШ_ТОКЕН_БОТА
   GUILD_ID=123456789012345678
   DATABASE_PATH=data/bot.sqlite3
   ```

   **GUILD_ID** = ID *сервера*, а не приложения. Получить: Discord → Настройки пользователя → Дополнительно → **Режим разработчика** → правой кнопкой по значку сервера → **Копировать ID**.

8. Запустите:

   ```powershell
   .\.venv\Scripts\python.exe bot.py
   ```

9. Администратор вызывает команду:

   ```text
   /setup_server crime_role:@Crime state_role:@State moderator_role:@Модератор
   ```

   Бот создаст:

   ```text
   📨・Заявки
     #подать-заявку             ← баннер, кнопка и приватные ветки заявок
     #журнал-заявок             ← только модераторы
   🎧・Приватные комнаты
     #управление-комнатой       ← Embed + 13 кнопок
     🔊 ➕ Создать комнату      ← вход для автоматического создания
   ```

10. Если бот офлайн, проверьте терминал. Чтобы остановить — `Ctrl + C`. Для работы 24/7 потребуется постоянно включённый компьютер или хостинг.

## 4. Проверяем на тестовом аккаунте

**Сначала анкета Crime:**

1. Тестовый участник без ролей Crime/State нажимает кнопку в `#подать-заявку`.
2. В форме вводит ник, статик, имя+возраст IRL, выбирает **Crime**, рассказывает о предыдущих семьях.
3. Попробуйте ввести в поле «Статик #» `12a45` — бот должен показать ошибку. Повторите, указав только цифры, например `001245`.
4. В дереве веток `#подать-заявку` модератор находит новую **приватную ветку** и нажимает «Принять».
5. Участник получает роль **Crime**, ветка удаляется, появляется запись в `#журнал-заявок`, а в ЛС отправляется сообщение об одобрении (если разрешено).

**Затем анкета State:** другой тестовый аккаунт выбирает **State** и после принятия получает именно роль **State**.

**Проверка отказа:** используйте аккаунт, который допустимо исключить. После кнопки «Отклонить» бот кикнет его, удалит ветку и попытается отправить ЛС. Бот пытается отправить уведомление об отказе **до исключения** (после кика Discord может блокировать новые ЛС). При закрытых личных сообщениях модератор увидит предупреждение, а журнал отметит отсутствие доставки.

**Проверка голоса:** зайдите в `➕ Создать комнату`, перейдите в `#управление-комнатой`, измените название/слоты и выйдите. Пустая комната должна удалиться.

**Проверка после рестарта:** остановите бота через `Ctrl+C`, затем снова `python.exe bot.py`. Старые рабочие кнопки продолжат реагировать, поскольку для них зарегистрированы постоянные обработчики. SQLite хранит связь ветки с заявителем и выбранное направление.

## 5. Команды

| Команда | Кто использует | Что делает |
|---|---|---|
| `/setup_server` | Администратор, только при установке на новый сервер | Создаёт каналы и панели, настраивает Crime/State |
| `/set_application_roles` | Администратор, в том числе после обновления старого проекта | Задаёт роли Crime и State; настраивает приватные ветки |
| `/republish_panels` | Администратор | Публикует свежие панели, включая баннер DYNASTY |
| `/reset_application user:@Участник` | Администратор | Сбрасывает зависшую анкету |
| `/bot_status` | Участники | Показывает состояние настройки |

## 6. Возможные проблемы

- **`ModuleNotFoundError: No module named 'discord'`** — установите зависимости командой ` .\.venv\Scripts\python.exe -m pip install -r requirements.txt` и запускайте именно ` .\.venv\Scripts\python.exe bot.py`.
- **`401 Unauthorized` / `Improper token`** — неправильное значение `DISCORD_TOKEN` в `.env` либо токен сброшен. Получите актуальный в Discord Developer Portal. Не публикуйте токен.
- **`403 Missing Access`** — неправильно указан `GUILD_ID`, бот не приглашён на сервер, не видит канал или отсутствуют права на приватные ветки. Выберите правильный сервер и проверьте канал `#подать-заявку`.
- **`Missing Permissions`** — отсутствуют права или роль бота ниже выдаваемой роли/роли исключаемого человека.
- **Кнопка не открывает окно** — бот не запущен, данные старой версии были оставлены или интерфейс Discord не обновлён. Убедитесь, что установлен `discord.py==2.7.1`.
- **ЛС не доставлено** — у человека выключены личные сообщения от участников сервера либо бот заблокирован. Это не влияет на решение.
- **Не отображается изображение** — файл `assets/dynasty_banner.png` должен существовать, а у бота должно быть разрешение `Attach Files`.
- **Не видно новые slash-команды** — проверьте `GUILD_ID`, scopes `applications.commands` и `bot`, потом перезапустите бота. Команды синхронизируются при запуске; Discord может показывать старые команды некоторое время.
- **Ветка не видна модератору** — у роли модератора должны быть **View Channel** и **Manage Threads** для `#подать-заявку`; командой `/set_application_roles` это разрешение настраивается автоматически.

## 7. Структура файлов

```text
discord_application_voice_bot/
├─ bot.py                  # Все Discord-команды и кнопки
├─ storage.py              # SQLite и безопасная миграция старой базы
├─ requirements.txt        # Python-зависимости
├─ .env.example            # Пример настройки (не секрет)
├─ .env                    # Создаёте сами; токен, не публиковать
├─ assets/
│  └─ dynasty_banner.png   # Ваша картинка для стартового Embed
├─ tests/
│  └─ test_storage.py      # Офлайн-тесты БД
└─ data/
   └─ bot.sqlite3          # Создаётся автоматически, сохранять при обновлениях
```

Для локальной проверки SQLite:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

**Обратите внимание:** статические проверки кода и SQLite не заменяют тест на реальном Discord-сервере. Тестируйте выдачу ролей, видимость приватных веток, модальные окна, ЛС и кик на тестовых аккаунтах до эксплуатации.
